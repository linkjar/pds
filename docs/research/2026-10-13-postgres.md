# Unit 11: the shared tier on Postgres

Date: 2026-10-13 · [Plan](../plan.md) · [SPEC §21.2](../SPEC.md#212-shared-tier-alternative) · [SPEC §8.4](../SPEC.md#84-storage-seams)

The accounts, the event log, the DID cache and the audit log of a server
can now be in Postgres. `migrate-storage` copies them between the two
backends.

## 1. Result

| Part | State |
|---|---|
| One SQL layer for both backends | Built: `pds_storage::sql`. |
| A Postgres client | Built in this repository: `pds_storage::pg`. |
| The four databases on Postgres | Built, for one server process. |
| `migrate-storage --to postgres` and `--to sqlite` | Built, with the comparison after the copy. |
| The lease of the event log | Built: a session advisory lock. |
| Several processes over the tier | Not built. |
| The switch on staging | The owner's. |

## 2. How it is built

- **One text for each statement.** The shared tier had about 140
  statements for SQLite. They stay as they are. `pds_storage::sql` runs a
  statement on either backend: it binds `?1` and `:name`, turns them into
  `$n` for Postgres, and gives the rows as values. Its names follow
  `rusqlite`, so the six modules changed their imports and little else.
- **Text on the wire.** Postgres checks the type of a binary parameter
  against its column. A parameter in the text format takes the type of
  the place it is used in, which is how SQLite treats a value. The client
  sends every parameter as text and reads every result as text, by the
  type of the column. The code above the layer needed no cast.
- **A client in this repository.** The `postgres` crate brings 25 crates
  that `cargo vet` has no audit for. The server needs a small part of the
  protocol: the start, SCRAM-SHA-256, one statement with parameters, a
  batch of statements, and the error of the server. That part is about
  500 lines on a blocking socket, with HMAC and PBKDF2 over the SHA-256
  the workspace has. A blocking socket also fits the code: every storage
  call is synchronous, as with SQLite.
- **The same tables.** The Reference's statements create the tables on
  Postgres after a change of type names (`integer` to `bigint`, `blob` to
  `bytea`, `autoincrement` to `bigserial`). Text gets `COLLATE "C"`, so
  an order and a comparison give what SQLite gives.
- **Reads that streamed.** Two reads of the event log walked a cursor of
  SQLite to its end or to a byte limit. They now read 64 rows for each
  statement, and the search for the last event of an account names its
  types in the statement.
- **One writer.** An append to the event log and to the audit log starts
  an immediate transaction. On Postgres that takes an advisory lock of
  the schema for the transaction, so sequence numbers and commits have
  one order.

## 3. How it is checked

The tests of Postgres run when `PDS_TEST_POSTGRES_URL` names a server.
The CI job starts one.

- `crates/pds-storage`: the layer on SQLite and on Postgres with the same
  statements; HMAC, PBKDF2 and SCRAM against the values of RFC 4231, RFC
  7914 and RFC 7677; the URL; the text format.
- `crates/linkjar-pds/tests/accounts.rs`: a server on Postgres over HTTP:
  an account, sessions, an app password, records, the firehose, admin
  actions, the ops listener, the audit log with a checkpoint, the lease.
- `crates/linkjar-pds/tests/oauth.rs`: a data directory copied to
  Postgres, an OAuth session with a refresh and a replay on the server
  over Postgres, and the copy back to files with the session in it.
- `crates/linkjar-pds/tests/cli.rs`: `migrate-storage` from the command
  line, its refusals, `verify` on Postgres, and `serve` with the lease.
- Every other test runs the shared tier through the layer on SQLite.
- The Harness, with `PARITY_CANDIDATE_POSTGRES=1`: the Candidate keeps
  its shared tier in the Postgres of the stack. The first run passed 18
  of the 22 default scenarios. `10-email` and `11-identity` failed on two
  statements in which Postgres cannot tell the type of a parameter; both
  are fixed, and a run of every integration test of the server on
  Postgres showed no other statement that fails. `02-sessions` and
  `21-oauth-negative` read `account.sqlite` in the container, which a
  server on Postgres does not have.

## 4. What is not built

1. **Several processes.** The replay set of DPoP proofs, the rate limits
   and the head of the event log that subscribers wait on are in the
   memory of one process.
2. **TLS to Postgres**, and the `md5` sign-in.
3. **Prepared statements.** Each statement is parsed by Postgres each
   time. The cost is not measured.
4. **`ops.sqlite` in the tier.** Operator roles and blocked email
   domains stay in the data directory.
5. **A fault test for Postgres.** The simulation of §19 injects faults
   below SQLite only.
6. **The Harness on Postgres in full.** Two scenarios read the SQLite
   file of the accounts. They need a reader for Postgres. The gate of the
   unit, the Harness green on both backends, is not met for these two.

## 5. Dependencies

`pds-storage` now uses `rand`, which the workspace had. `cargo vet` needs
no new exemption.
