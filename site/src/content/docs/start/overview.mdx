## Get a server running

Follow these pages in order for a new installation. The guide uses Docker
Compose with Caddy for HTTPS and a local data directory for SQLite and blobs.
For a native deployment, use the [Nix or binary installation guide](/start/native/)
for the installation step.

<Steps>

1. **[Prepare the host](/start/requirements/)**

   Check Docker, storage, network access, and the domain you will use.

2. **[Set up DNS](/start/dns/)**

   Point the server name and account handles at your host.

3. **[Install with Docker Compose](/start/install/)**

   Pin the image, generate secrets, and check the configuration before starting.

4. **[Verify the setup](/start/verify/)**

   Check HTTPS, server metadata, and health from outside the host.

5. **[Create your first account](/start/first-account/)**

   Make an invite, create an account, and sign in with a client.

</Steps>

<Aside title="Before hosting other people's data">
	Set up [email for account recovery](/configure/email/), keep a tested
	[backup](/operate/backup/), and review the
	[authentication limits when rolling back](/operate/update/#roll-back).
	A database that an older server can read does not guarantee the same
	credential-revocation protection.
</Aside>

## Understand the system

The [architecture guide](/reference/architecture/) explains the server's
parts and data files. For larger deployments, start with
[Postgres](/scale/postgres/) or the [entryway and member model](/scale/entryway/).
If a check fails, use the [troubleshooting guide](/reference/troubleshooting/).

These pages describe LinkJar PDS. The upstream
[AT Protocol documentation](https://atproto.com/) explains the protocol,
and its [self-hosting guide](https://atproto.com/guides/self-hosting)
links to the reference server. LinkJar's implementation and deployment
instructions are maintained in the [source repository](https://github.com/linkjar/pds).
